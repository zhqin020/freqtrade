
# Box Theory DCA Strategy - 深度技术文档

## 1. 核心设计理念 (Architecture)

本策略融合了 **尼古拉斯·达瓦斯 (Nicolas Darvas) 的箱体理论** 与 **动态马丁格尔 (DCA)** 仓位管理。它采用 **MTF (Multi-Timeframe)** 多周期架构，将市场划分为三个逻辑层级：

*   **4H (大区 - 趋势层)**: 使用 EMA 200 确定主趋势，并作为最后的止损防线。
*   **1H (中区 - 结构层)**: 生成核心交易箱体。这是识别“突破”与“回调”的主要依据。
*   **15m (小区 - 执行层)**: 所有的入场触点和 DCA 加仓动作均在该周期进行，以确保捕捉最精准的价格波峰/波谷。

---

## 2. 三大入场模式 (Entry Logic)

策略通过三种互补的模式来捕获波段：

1.  **趋势突破 (Breakout Long/Short)**:
    *   **逻辑**: 当大趋势看多，且价格以**高于平均水平 3 倍的成交量**冲破 1H 箱体顶部时入场。
    *   **目的**: 捕捉加速上涨或下跌行情。
2.  **假突破反转 (Fake Breakout Long/Short)**:
    *   **逻辑**: 价格瞬间刺穿箱体边缘，但无法维持动能（成交量萎缩），随后迅速收回到箱体内。
    *   **目的**: 识别机构“扫单”行为，进行缩量反转操作。
3.  **箱底/箱顶回调 (Pullback Long/Short)**:
    *   **逻辑**: 在大趋势看多时，价格回撤至 1H 箱体底部，且**卖盘动能衰竭 (Volume SMA < 0.9)**。
    *   **目的**: 以极高的盈亏比提前布局，不需要等突破即可低位上车。

---

## 3. DCA 仓位与安全机制 (Position Management)

这是策略最核心的防御逻辑，旨在应对单边下跌。

### DCA 触发条件
补仓必须同时满足两个硬性指标：
1.  **价格偏离度**: 当前价必须比**上一次成交价**降低了 `dca_min_pct` (1.5% - 2%)。
2.  **形态确认**: 价格必须处于 1H 或 15m 箱体的底部（支撑位）。

### 三重安全防护
*   **挂单保护 (Open Order Check)**: 如果当前已经有一个加仓单在撮合中，策略将拒绝新的加仓指令，防止在闪崩行情中同一秒密集下单导致爆仓。
*   **价格锚定 (Last Price Anchor)**: 不同于普通 DCA 对比“开仓均价”，本策略锚定“**最后一次实盘成交价**”，确保加仓间距是真实的几何级数，而非无效刷单。
*   **大区趋势熔断 (HTF Stop)**: 如果价格跌破了 **4H 级别的箱体底线**，策略会判定这不再是“回调”，而是“崩盘”，此时会停止所有 DCA 动作并止损出局。

## 4. 参数表 (Parameter Glossary)

| 参数名 | 默认值 | 定义与作用 |
| :--- | :--- | :--- |
| **`box_window_1h`** | 12 | 1H 箱体计算周期。越小箱体越灵敏，越大则结构越稳定。 |
| **`box_window_4h`** | 54 | 4H 趋势锚点。决定了策略对主趋势及其边界的判断范围。 |
| **`dca_min_pct`** | 0.015 | **DCA 步进**。每次补仓之间必须拉开 1.5% 的空间。 |
| **`max_entry_count`** | 5 | **子弹总数**。包含首单在内，最多进行 5 次投入。 |
| **`breakout_volume_threshold`** | 2.99 | **突破量倍数**。要求突破时的量必须是平时的 3 倍，过滤假突破。 |
| **`volume_exhaustion_threshold`** | 0.91 | **成交量衰竭系数**。低于此值表示反转几率增加。 |
| **`leverage_val`** | 1 | **杠杆**。寻优建议设为 1x，您可以根据回撤承受能力调大。 |
| **`stoploss`** | -0.197 | **硬止损**。考虑到 DCA 需要波动空间，寻优建议在 -19.7% 或离场信号触发时平仓。 |

---

## 5. 如何评估和微调？

*   **如果交易太频繁？** -> 提高 `breakout_volume_threshold` 或减小 `box_window_1h`。
*   **如果不加仓？** -> 检查 `dca_min_pct` 是否设得太大，或者加仓上限 `max_entry_count` 已满。
*   **如果回撤太大？** -> 降低 `leverage_val`，或者将 `max_entry_count` 限制在 3 以内。
