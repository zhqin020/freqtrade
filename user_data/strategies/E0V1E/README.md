# my strategies
读完策略代码，下面是完整分析。

---

## 策略结构总览

**E0V1E** 是一个 1h 双向（多空）策略，核心思路是：**RSI 背离/极值 + SMA 偏离 + CTI 过滤 → 逆势低吸/高空，再配合多层动态离场机制退出**。

---

## 入场逻辑

### 做多（两套条件并联）

| | buy_1 | buy_new（更激进） |
|---|---|---|
| 趋势过滤 | rsi_slow 下降 | rsi_slow 下降 |
| 超卖过滤 | rsi_fast < 57 | rsi_fast < 34（更严格） |
| 反弹信号 | rsi > 49 | rsi > 28 |
| 价格位置 | close < sma15 × 0.975 | close < sma15 × **0.96**（更深回撤） |
| 趋势强度 | cti < -0.75 | cti < cti参数值 |

`buy_new` 需要价格跌到均线下方 4%，属于深度回撤抄底，自定义止损会给它更宽松的保护（盈利 3% 才开始追踪）。

做空与做多完全对称镜像。

---

## 离场逻辑（全部依赖 custom_exit，ROI 设为 100% 实际禁用）

离场分四层：

```
1. 盈利退出    fastk > 84（多）/ fastk < 16（空）→ 随机动量出场
2. 解套退出    min_profit <= -10% 且当前已回到 -5% 以上 且 CCI 极值 → 接近解套时快速止盈
3. TMP_HOLD机制    价格站上/下 ma120 且 ma240 → 加入"持有池"，等待趋势延续
4. TMP_HOLD1机制   开仓价与ma120差距 >= 10% → 加入"快出池"，价格一进ma120就马上退出
```

**自定义止损**：
- 利润 ≥ 5%：追踪止损缩窄到 -0.2%（锁利）
- buy_new/short_new 利润 ≥ 3%：追踪止损 -0.3%
- 其余情况：不收紧，沿用固定 -25%

---

## 关键问题与风险

### 1. 全局变量 `TMP_HOLD` / `TMP_HOLD1` 是严重缺陷

```python
TMP_HOLD = []   # 模块级全局列表
TMP_HOLD1 = []
```

- **回测时**：freqtrade 多进程/多对并行时，不同交易对的 trade.id 会混入同一个列表，导致持仓逻辑串扰，回测结果**不可信**。
- **实盘时**：重启进程后列表清空，所有已记录的持仓状态丢失，持仓逻辑失效。
- 正确做法应使用 `trade.custom_info` 字典或数据库字段持久化状态。

### 2. RSI 周期异常偏长

```python
buy_rsi_period = 83     # 默认
buy_rsi_fast_period = 121
buy_rsi_slow_period = 139
```

在 1h 周期上，83根K线的 RSI 相当于约 3.5 天的超长平滑，几乎常年在 50 附近，失去超买超卖辨别力。这三个参数的优化范围是 10~190，默认值接近中间，**大概率是过拟合产物**。

### 3. 冷却期保护与高频入场冲突

`CooldownPeriod: 18 candles = 18小时`。1h 图加上 18 小时冷却，意味着每对每天最多交易一次，策略实际交易频率会大幅低于预期。

### 4. 盈利止损极紧

利润一过 5% 就把止损收到 -0.2%，意味着一根 K 线的正常回调就会被踢出去。在 1h 的波动下，**大量正确的趋势交易会被过早结束**。

---

## 优点

- 双向交易设计完整，多空对称，适合趋势/震荡均有的市场。
- CTI 过滤是个相对独特的过滤器，能有效过滤横盘噪音。
- custom_exit 的多层逻辑思路合理（解套退、趋势持、快速锁利）。
- `startup_candle_count = 240` 合理覆盖 ma240 预热需求。

---

## 总结评价

| 维度 | 评价 |
|---|---|
| 逻辑设计 | 思路清晰，双向对称 ✅ |
| 全局变量缺陷 | 严重问题，回测结果不可信 ❌ |
| 参数过拟合风险 | RSI 周期偏长，高度依赖历史数据 ⚠️ |
| 止损机制 | 利润保护过紧，趋势持仓容易被踢出 ⚠️ |
| 实盘稳健性 | 需先修复全局变量问题才能回测/实盘 ❌ |

**建议**：先把 `TMP_HOLD` / `TMP_HOLD1` 改为基于 `trade.id` 的持久化方式（可用 `Trade.get_overall_performance()` 或直接在 `custom_stoploss` 中用 `current_profit` 替代状态机），再做回测验证参数有效性。
